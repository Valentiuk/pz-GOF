# Практичне заняття: pz-GOF
## Реалізація патернів Gang of Four (TypeScript)

### Реалізовані патерни
1.  Singleton : Гарантує один екземпляр бази даних.
2.  Factory Method : Створення різних типів доставки (Road/Sea).
3.  Builder : Покрокове створення об'єкта Pizza.
4.  Adapter : Адаптація квадратної деталі до круглого отвору.
5.  Facade : Спрощення інтерфейсу конвертації відео та аудіо.
6.  Strategy : Зміна алгоритму побудови маршруту (Road/Walking).
7.  Observer : Система підписки клієнтів на новини магазину.

---
## Детальний опис та аналіз патернів

### 1. Породжувальні патерни

####  Singleton 
*  Яку проблему вирішує:  Запобігає створенню кількох екземплярів класу, які керують спільним ресурсом (наприклад, підключення до БД або конфігурація).
*  Порівняння:  Без нього кожен модуль створював би нове підключення, що призвело б до вичерпання лімітів БД та надмірного споживання пам'яті.

####  Factory Method
*  Яку проблему вирішує:  Дозволяє створювати об'єкти, не вказуючи їхні конкретні класи в коді, що їх використовує.
*  Порівняння:  Замість жорсткого хардкоду `if (type === 'truck') new Truck()`, ми делегуємо створення підкласам, що дозволяє додавати нові типи транспорту без зміни існуючого логістичного коду.

####  Builder 
*  Яку проблему вирішує:  Дозволяє створювати складні об'єкти покроково. Вирішує проблему "телескопічного конструктора" (коли у конструкторі 10+ параметрів).
*  Порівняння:  Код стає набагато читабельнішим: `builder.setSauce().setCheese().build()` замість `new Pizza("Tomato", "Mozzarella", null, true, ...)`.

---

### 2. Структурні патерни (Structural)

####  Adapter
*  Яку проблему вирішує:  Дозволяє об'єктам із несумісними інтерфейсами працювати разом.
*  Порівняння:  "Анти-приклад" вимагав би переписування всієї логіки сторонньої бібліотеки під наш формат. Адаптер створює "прошарок", залишаючи оригінальний код недоторканим.

####  Facade
*  Яку проблему вирішує:  Надає простий інтерфейс до складної системи класів, бібліотеки або фреймворку.
*  Порівняння:  Клієнту не потрібно знати про ініціалізацію відеопотоку, декодування аудіо та роботу з пам'яттю. Він просто викликає `convert()`, а Фасад керує десятком підсистем.

---

### 3. Поведінкові патерни (Behavioral)

####  Strategy
*  Яку проблему вирішує:  Дозволяє змінювати алгоритм (наприклад, метод розрахунку маршруту) прямо під час виконання програми.
*  Порівняння:  Замість гігантського `switch-case` всередині одного методу, кожен алгоритм винесено в окремий клас. Це полегшує тестування та підтримку.

####  Observer
*  Яку проблему вирішує:  Створює механізм підписки, що дозволяє об'єктам реагувати на події в інших об'єктах без жорсткого зв'язку між ними.
*  Порівняння:  Без нього об'єкт `Store` мав би знати про кожного покупця особисто і викликати їхні методи вручну, що зробило б систему неможливою для розширення.

---

### Запуск та перевірка
Проєкт використовує `ts-node` для запуску TypeScript файлів без попередньої компіляції.

Команди:
```
npm install
npm start
```
